
# ExplainCrop

An explainable, multi-crop nutrient deficiency detection and fertilizer
recommendation system using a crop-conditioned Vision Transformer.

## What makes this different from existing published work

See `paper/novelty_notes.md` (to be added) for the full comparison, but in
short:

1. **Crop-conditioned attention** — one shared ViT backbone, with a learned
   per-crop token that conditions self-attention, instead of training
   separate models per crop or naively pooling all crops together.
2. **Disease-vs-deficiency disentanglement** — a first-stage "cause" head
   (healthy / deficiency / disease / pest) trained jointly across ALL
   crops, including disease-only crops with no deficiency labels (cotton).
3. **Few-shot transfer to data-scarce crops** — cotton has no public
   deficiency dataset; the model adapts to it via few-shot learning on top
   of the shared backbone instead of being excluded.
4. **Uncertainty-aware severity + recommendation** — severity is predicted
   as a distribution (mean + variance), and the fertilizer recommendation
   engine scales its confidence down when the model is unsure, using both
   the severity variance and the Grad-CAM affected-area ratio.

## Project structure

```
ExplainCrop/
├── config.py            # class taxonomy, hyperparameters, paths — single source of truth
├── dataset.py            # unified loader; normalizes every raw dataset into one schema
├── models.py              # CropConditionedViT architecture
├── severity.py             # weak severity labeling (HSV heuristic, see caveats below)
├── explain.py               # Grad-CAM explainability (to be added)
├── recommendation.py         # fertilizer recommendation engine (to be added)
├── train.py                    # training loop (to be added)
├── app.py                       # Streamlit dashboard (to be added)
├── requirements.txt
├── datasets/
│   ├── raw/               # place downloaded datasets here (see below)
│   └── manifest.csv        # generated by `python dataset.py`
├── checkpoints/             # trained model weights
├── outputs/                   # predictions, plots, evaluation results
├── notebooks/                   # EDA / experiments
└── paper/                         # IEEE paper drafts, figures, tables
```

## Dataset acquisition (manual step — no dataset ships with this repo)

Downloads require Kaggle/Roboflow/Mendeley accounts and were not fetched
automatically. Place each dataset under `datasets/raw/<source_name>/` using
the folder names below — these exact names are what `dataset.py`'s
`RAW_LABEL_MAP` expects. If you rename a folder, update the map.

| Folder name | Source | Notes |
|---|---|---|
| `rice_npk_kaggle` | Kaggle: Nutrient-Deficiency-Symptoms-in-Rice | ~1,155 images, N/P/K |
| `rice_disease_kaggle` | Kaggle: Rice Leaf Diseases (vbookshelf) | disease-only, for disentanglement |
| `maize_npk_kaggle` | Kaggle: Maize Plant Leaf Nutrient Deficiency Dataset | |
| `tomato_deficiency_roboflow` | Roboflow: tomato deficiency sets | N/K/Mg/Fe |
| `tomato_plantdoc` | Roboflow: PlantDoc-Tomatoes | disease-only, field images |
| `wheat_n_deficiency_kaggle` | Kaggle: Wheat Nitrogen Deficiency & Leaf Rust | |
| `cotton_disease_kaggle` | Kaggle: cotton leaf disease dataset | disease-only, no deficiency labels exist publicly |
| `banana_deficiency_mendeley` | Mendeley: banana nutrient deficiency (Sunitha et al.) | 8 micronutrient classes |
| `coffee_coleafdb_mendeley` | Mendeley: CoLeaf-DB | Peruvian coffee deficiency |

After placing raw data:

```bash
python dataset.py     # builds datasets/manifest.csv, warns about unmapped folders
```

## Known limitations to state explicitly in the paper

- Severity labels are weakly supervised (HSV-based heuristic), not
  ground-truth annotated — validate against a small hand-labeled subset
  before reporting severity metrics.
- No public cotton deficiency dataset exists — cotton is handled via
  few-shot transfer, not full supervision; report this as a limitation,
  not a hidden gap.
- The crop-conditioning token adds 1 extra sequence position beyond what
  the pretrained ViT positional embeddings were sized for — positional
  embeddings need interpolation/fine-tuning at training start (handled in
  `train.py`, flag if you see shape mismatches).
